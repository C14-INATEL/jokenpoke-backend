## User Story

> **Como** jogador com um deck configurado,  
> **eu quero** iniciar uma batalha contra outro jogador através da API,  
> **para que** o sistema processe os rounds automaticamente com base nas regras de fraqueza entre movimentos e me retorne o resultado estruturado com os rounds disputados e o vencedor final.

---

## Contexto / Motivação

A funcionalidade de batalha existia parcialmente no backend, mas a lógica de negócio não estava conectada à API. A regra de comparação entre movimentos precisava ser refinada e centralizada em `MOVE_WEAKNESS`, e o caso de uso `StartBattleUseCase` precisava ser finalizado para validar decks, processar rounds e retornar um resultado coerente. Nesta iteração, o atacante é fixado como o usuário de ID 1, com a substituição por autenticação JWT prevista para uma história futura.

## Critérios de Aceitação

### AC-01 — Execução de batalha com resultado estruturado

```gherkin
Given  dois jogadores, atacante e defensor, ambos com deck configurado
When   o cliente envia POST /battle/{defender_id}
Then   a resposta HTTP deve ser 200
And    o body deve conter a lista de rounds disputados
And    cada round deve indicar os movimentos usados e o resultado do round
And    o body deve conter o vencedor final da batalha
```

---

### AC-02 — Validação de deck do atacante

```gherkin
Given  o atacante (usuário fixo de ID 1) sem deck configurado
When   o cliente envia POST /battle/{defender_id}
Then   a resposta HTTP não deve ser 200
And    o body deve conter uma mensagem de erro indicando que o atacante não possui deck
```

---

### AC-03 — Validação de deck do defensor

```gherkin
Given  o defensor identificado por {defender_id} sem deck configurado
When   o cliente envia POST /battle/{defender_id}
Then   a resposta HTTP não deve ser 200
And    o body deve conter uma mensagem de erro indicando que o defensor não possui deck
```

---

### AC-04 — Aplicação das regras de fraqueza entre movimentos

```gherkin
Given  uma batalha em andamento entre dois jogadores com deck configurado
When   os movimentos de cada round são comparados
Then   o resultado de cada round deve seguir as regras definidas em MOVE_WEAKNESS
And    nenhum número mágico deve ser utilizado na lógica de comparação
```

---

- O **atacante está fixado como usuário de ID 1** nesta iteração. A substituição por autenticação JWT via token está planejada para uma história futura (relacionada ao PR #24 — US-002).
